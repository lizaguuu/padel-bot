# 🎾 Padel-бот: свободные корты Mitte Cabrio → Telegram

Проверяет Playtomic **раз в минуту** (mitte — the cabrio | wandsbek) и пишет в Telegram-группу, когда освобождается корт:
- **будни** — слоты с 17:30 и позже
- **выходные** — любое время
- 14 дней вперёд, только парные (double) корты, игры на 60/90/120 минут

Работает бесплатно на GitHub Actions, свой компьютер или сервер не нужен.

---

## 1. Создай бота в Telegram (2 мин)
1. Открой **@BotFather** → `/newbot` → задай имя и username (например `mitte_padel_bot`).
2. Скопируй **токен** вида `1234567890:AAH...`.
3. Создай группу, добавь туда бота и друзей.
4. Напиши в группе: `/start@имя_твоего_бота`.

## 2. Узнай ID группы
Открой в браузере (подставь свой токен):
```
https://api.telegram.org/bot<ТОКЕН>/getUpdates
```
Найди `"chat":{"id":-100...` — это и есть **TELEGRAM_CHAT_ID** (с минусом).
Если ответ пустой, напиши в группу ещё раз `/start@имя_бота` и обнови страницу.

## 3. Залей проект на GitHub
1. github.com → **New repository** → имя `padel-bot` → **Public** (для публичного репозитория минуты Actions бесплатные и без лимита; токен всё равно спрятан в Secrets).
2. **Add file → Upload files** → загрузи `padel_watch.py` и `README.md`.
3. **Add file → Create new file** → в поле имени впиши `.github/workflows/padel.yml` → вставь содержимое `padel.yml` → **Commit**.

## 4. Добавь секреты
Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:
- `TELEGRAM_TOKEN` — токен от BotFather
- `TELEGRAM_CHAT_ID` — id группы

## 5. Запусти и проверь
**Actions → padel-watch → Run workflow**:
1. `mode` = `--test` → в группе должно появиться «✅ Padel-бот подключён».
2. `mode` = `--dump` → открой лог шага *Check Playtomic* и сравни пару слотов с приложением Playtomic.
   **Если время везде сдвинуто ровно на 1 час** — в `padel_watch.py` поменяй `API_TIMES_ARE_UTC = ...` на `API_TIMES_ARE_UTC = False`.
3. `mode` = `check` → первый запуск пришлёт список того, что свободно сейчас, дальше — только о новых освободившихся слотах.

Дальше всё работает само по расписанию.

---

## Настройки (верх файла `padel_watch.py`)
| Параметр | Что делает |
|---|---|
| `WEEKDAY_FROM = "17:30"` | с какого времени в будни |
| `WEEKEND_FROM = "00:00"` | с какого времени в выходные |
| `DAYS_AHEAD = 14` | на сколько дней вперёд смотреть |
| `DURATIONS = {60, 90, 120}` | какие длительности игры показывать (например, только `{90}`) |
| `ONLY_DOUBLE_COURTS = True` | `False` — показывать и одиночные корты |
| `--loop 60 1200` в `padel.yml` | 60 = пауза между проверками (сек), 1200 = сколько длится один запуск (сек) |

## Важно знать
- Как это устроено: GitHub запускает задачу каждые 10 минут, а каждая задача ~20 минут сама проверяет корты раз в минуту. Пока одна работает, следующая ждёт в очереди, так что проверки идут без перерывов (между запусками бывает пауза ~1 минута).
- В списке Actions будут появляться запуски со статусом *Cancelled*. Это нормально: GitHub держит в очереди только один ожидающий запуск, а лишние отменяет.
- Чаще чем раз в 30–60 секунд ставить не советую: Playtomic может начать блокировать слишком частые запросы.
- Если в репозитории 60 дней нет никаких коммитов, GitHub ставит расписание на паузу и присылает письмо. Тогда зайди в Actions и нажми **Enable workflow**.
- Используется неофициальный публичный API Playtomic (тот же, что у сайта). Если Playtomic его поменяет, бот перестанет находить слоты. Тогда запусти `--dump` и посмотри ошибку в логе.
